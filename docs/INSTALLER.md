# Windows installer and first-run setup

## DigView identity change (2026-10-22 source)

The next package uses `digview.exe` and `app.digview.desktop`. Quit every previous app instance before installing/launching it. On Windows, first launch imports the previous owned application-data folder, including the library and WebView profile, into the new location without deleting the original. The retained old directory remains excluded from scanning and file actions, even when a selected parent folder contains it. A failed import stops startup instead of silently opening an empty library; retained staging folders may need review. Existing new libraries are never overwritten. Known startup opt-in and browser preferences migrate to DigView names.

This identity change requires a new build and disposable migration/installed-upgrade validation. Earlier installer results below do not validate it. New app identity may affect OS install/uninstall registrations and startup permissions; do not assume an in-place upgrade merely because the product version is unchanged. macOS/Linux data migration is not implemented.

## Delivered flow

1. Standard Tauri NSIS installer with the approved DigView green icon, header and sidebar. Current-user installation, directory/shortcuts, standard upgrade and uninstaller behavior. The final Run DigView option opens the app when selected.
2. Branded first-launch setup fills the app window with one flat surface: **Welcome → Folders → Search → Preferences**. There is no inset frame/shadow or separate settings-summary Review screen.
3. The folder step suggests Documents, Pictures, Videos, Music, Desktop and Downloads using actual OS known-folder locations, including configured redirections. New suggestions start unchecked. Missing locations are disabled; covered existing roots are checked/read-only, and parents overlapping an existing root are disabled with an explanation. A checkbox explicitly grants a draft selection only. Choose custom folder uses the native picker; optional relative exclusion rules remain available. No new roots are registered or scanned while choosing.
4. Filename/filter search is available by default. Supported document keyword indexing is optional and defaults off. No model download is required.
5. Choose Light/Dark/System, tray behavior, optional Windows login startup, reduced resource use and battery pause. Ctrl+F is an in-app shortcut.
6. Choose **Start using DigView** on Preferences. Selected roots, exclusions, document preference and completion are saved together before indexing starts. With new/existing registered folders, open the library directly. Only a no-root library shows the optional final Add folders/Open my library screen. Indexing status appears in the library; a scan-start failure is transferred as a library recovery notice. If native library opening fails after saving, retry opening without resaving setup.

**Set up later** adds no new folders and retains your existing library/settings; on a fresh device it opens an empty library. Add folders later through the existing library/Settings flow. Version 2 completion requires actual confirmation: older version-1 auto-completion markers show the corrected wizard once on upgrade. Completing or choosing Set up later prevents reopening on normal restarts/reinstalls with retained app data. There is no Settings reopen action or native reset command; preferences remain editable independently. Existing roots/settings load into setup and existing folders are shown separately; they are not removed or re-added. Already-authorized indexing may continue; if it blocks a save, stop the current indexing task from the error panel and retry. App ID and binary identity stay stable for continuity.

## Persistence and boundaries

The optional empty-library completion screen offers **Add folders** inline in the same setup surface; successful registration opens the library directly. The library/empty-state/Settings Add folder controls open the shared selection dialog. Both use the same `FolderSelection` controls from onboarding; **Choose custom folder** opens the native picker. After setup, **Add selected folders** validates and commits up to 32 choices atomically; existing roots, preferences and completion state stay intact. Cancel/close discards pending grants without registering folders. Busy library jobs prevent the commit until finished/cancelled; a scan-start race after a successful save shows a recovery warning. This is a folder-only view, not a wizard restart. Source-only until the user's next build; runtime validation remains pending.

`native-core/src/setup.rs` owns the SQLite completion state and in-memory explicit native-selection grants. Renderer completion requests contain opaque tokens, not arbitrary filesystem paths. The suggested-folder command accepts only six known keys, resolves their locations natively and grants them only after the user checks a choice; listing metadata grants nothing. Choices expire on process restart; unfinished folder drafts must be selected again. Completion revalidates canonical locations, rejects overlapping/unavailable/redirected choices and app-data children, and commits roots/preferences/completion atomically. Selection alone never registers roots. The existing selected-root watcher and scan policy enforce containment and app-data exclusions.

Background/Windows-startup preferences are saved separately before core completion; these preferences can already be saved if a later step fails. Appearance applies when selected. Setup remains open on error with retry; the core transaction publishes no partial folder state. Repeated completion is idempotent. Existing selected-root jobs continue after opening the library or hiding to tray.

There is no account screen, activation gate, Gemma download, semantic search, global search hotkey or synthetic speed calibration in this milestone. A browser-only visual demo at `?setup=1` is explicitly labeled; it cannot scan or save native preferences.

## Build and validation

### Manual local-development reset

Quit DigView through tray **Quit**, then double-click root `Reset-Onboarding.cmd`. Python 3 is required (already a local build prerequisite). The helper refuses known running app executables, opens only the existing `%LOCALAPPDATA%/app.digview.desktop/library.sqlite3` in read/write-without-create mode, saves the old completion marker as a small JSON backup beside that database, and resets only `setup_state` row 1. Roots, file index, favourites and preferences remain intact. Open the current DigView build to see setup again. This is an explicit workspace helper, not an automatic reset or a Settings reopen action; there is no app rebuild needed for the helper itself. Setup preferences remain independently editable in normal Settings after completion.

Use `node scripts/build-windows.mjs` or `Build-Windows.cmd`; see the root build guide. Generated EXE/NSIS files are placed in a unique release directory and are not launched or installed automatically. Installer bitmap sources are `scripts/prepare-installer.ps1` and its Node launcher; reproduce with `node scripts/prepare-installer.mjs` on Windows after regenerating native icons. Checked-in header is 150×57, sidebar 164×314, both 24-bit BMP.

Implementation checks cover draft authority, expiration, canonical revalidation, overlap/refusal, rollback, migration, empty completion, durable/idempotent state and orchestration order/failure recovery. Installation/uninstallation, installed upgrade preservation and native WebView picker-to-library smoke require a separate disposable Windows validation. See STATUS.md for actual build/check outcomes. Source checks do not establish installed runtime validation.
