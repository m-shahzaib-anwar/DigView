# Architecture and decisions

Short setup routing: four screens (Welcome/Folders/Search/Preferences), with durable completion from the Preferences action. Registered new or existing roots route directly to the library; only no-root completion renders the optional final screen. Its shared Add folders view is embedded in the full-window setup surface, while normal library/Settings entry points remain modal. A failed native open exposes retry without resaving setup, and a session-only notice hands scan-start warnings to the library toast. Setup CSS has no outer inset frame/border/shadow; focus outlines remain.

`folder-selection.tsx` renders the common suggested/custom draft controls for onboarding and `AddFoldersDialog`. The latter is opened from completion/library/Settings and uses the extracted shared `Modal`. `add_chosen_folders` invokes `Engine::add_folder_choices` on a blocking worker: under the operation gate it validates existing completion, idle job, opaque draft authority, canonical containment and overlaps, inserts the selected roots in one transaction, consumes their grants and increments the revision. It does not modify setup/settings. Cancel/removed custom choices call `discard_folder_choices` for bounded in-memory cleanup. The UI starts scan after durable registration, tolerates a watcher race and never resubmits already-saved roots on a refresh failure.

Suggested setup folders: the desktop adapter resolves six allowlisted known-folder keys through Tauri's native path resolver. Listing checks directory availability/canonical identity and existing-root coverage on a blocking worker without obtaining grants. The explicit checkbox command resolves the key again and calls the same native draft-grant path as the picker. Renderer paths never authorize filesystem access. New selected tokens are committed only by the existing final setup transaction.

2026-10-21 first-run setup: `setup.rs` owns a versioned SQLite completion row and process-local native-picker grants. `finish_setup` revalidates token-authorized canonical roots and atomically saves roots, scan/content preferences and completion under the operation gate. Version 2 requires actual confirmation; legacy version-1 auto-completion shows the corrected wizard once. Completion/Set up later persists across restarts/reinstalls with retained data; no reopen/reset command is exposed. The wizard seeds its controls from existing preferences and lists existing roots separately. `SetupGate` mounts the library after setup; `setup-plan.ts` orders background preference save → durable completion → scan, with retry-safe scan warnings. The adapter sizes the first-run window separately and forces incomplete setup visible even for a login launch. See INSTALLER.md for persistence/failure boundaries.

2026-10-20 additions: `content_preview` in native-core validates indexed IDs, selected roots/exclusions and metadata before/after file access. Text reads are capped at 256 KiB. PDF (up to 40 MiB) and media are served to the main WebView via `digview-preview` protocol using 256-bit opaque grants, max eight live sessions, one-hour idle expiry and explicit revocation. Media responses read at most 2 MiB per request, with HTTP single ranges/HEAD/416 and seek support. File I/O runs on native blocking workers; root removal, exclusions or metadata changes invalidate reads. No general asset filesystem permission or renderer-supplied path was added.

`src/file-preview.tsx` selects read-only text, HTML media or PDF.js canvas previews. PDF parsing uses a bundled module worker with local CMaps/fonts/WASM/ICC resources; active document scripting, external embedded viewers and interactive annotation layers are absent. PDF output is capped at 8 million canvas pixels and a 4096-pixel raster dimension; large images are limited independently. Existing image/OCR paths remain.

`native-core/src/local_diagnostics.rs` writes/rotates bounded JSONL logs, sanitizes frontend fields again and exports only known generated log files. The desktop adapter handles save/open dialogs on blocking workers and normal app exit. Native panics record source location; an open-session marker detects the previous unclean exit on next startup. Frontend global error/rejection listeners, React boundary, API failures and job transitions report only allowlisted metadata and source locations. This always-local logger is independent of the disabled optional cloud channels; see DIAGNOSTICS.md.

## Product

A local visual file library with discovery, OCR and review-first cleanup. Use original branding and assets. Match the verified behaviors; do not build an unrelated generic Explorer clone.

## Layers

The reusable engine lives in the independent `native-core` crate. Tauri is a thin adapter in `src-tauri`. Core tests and benchmarks run without resolving or compiling the GUI framework; desktop packaging links the same engine source.

1. React/TypeScript: responsive desktop shell, virtualized library, previews, filters, progress and review dialogs. UI never receives broad filesystem authority.
2. Tauri commands: typed request/response boundary. Use native picker, register only explicitly selected roots. Validate file IDs and paths against persistent root membership before opening, previewing, OCR or trash.
3. Rust engine: background jobs, walkdir without symlink following, bounded event updates, staged index reconciliation, streaming hashes, thumbnail cache and on-device OCR adapters.
4. SQLite: WAL, busy timeout, roots/files index, FTS5 filenames, indexed category/size/date/source. Stable ordering and pagination. One database connection per short operation; do not keep a database lock while reading/hashing image contents.
5. Platform adapters: default application opening, native trash, OCR and origin metadata.

## Safety

The desktop adapter owns the tray and background preferences, separate from the core watcher. The main window starts invisible to avoid flashing during login startup, then shows on manual launch. Close interception is conditional on the saved background preference and a successful hide; tray Quit exits the process. Startup uses a fixed per-user Windows Run value, not an elevated task/service or a shell command. Preferences persist in app-local `background.json`; OS registration and preference writes run on a blocking worker, serialize under a mutex, and errors are surfaced in settings. Startup and app identity keys remain stable across display branding changes. UI gains only two narrowly scoped settings commands and no registry/filesystem API permissions.

`native-core/src/watcher.rs` owns a native `notify` service, started once by the Tauri adapter. Its callback sends hints through a bounded 4096-event channel; a worker tracks up to 4096 paths and applies at most 256 settled file events per tick. Ordinary file updates are incremental. Directory changes, startup/new root attachment, overflow and reported event loss schedule a background recovery scan. Recent files are deferred without purging their old rows. The existing task/operation gates serialize watcher writes with manual scans, hashing, root changes and trash; interrupted recovery retains retry work. Root subscriptions sync every second, and each mutation independently revalidates current database membership and canonical containment. UI polling carries a monotonic index revision so a short watcher batch cannot be missed between polls. No automatic hashing, OCR, trash or indexing of arbitrary roots is added.

- Directory selection is explicit; no automatic home-drive scan.
- Store canonical paths, never follow symlink escapes. Only registered paths may be read through commands.
- Reconcile missing files only after a successful complete scan of a root. Cancellation/errors must not purge a healthy index.
- Confirm trash in UI and recheck root containment, size and modification time in Rust. Hash again when duplicate safety depends on content identity. No permanent delete fallback.
- Treat metadata URLs as untrusted: only display parsed hostname, never execute metadata commands.
- Only image asset protocol paths scoped by the native backend may load. Thumbnails are rasterized; SVG/HTML never execute as local previews.
- File contents, OCR and library data remain local. No account provider, sign-in screen, auth request bridge or account-session vault is present. Optional signed updates and disabled cloud telemetry are separate facilities. Existing app-data paths preserve the device library.

## Search

Local deterministic parser maps phrases to structured category, date interval, minimum/maximum size and remaining filename terms. Calendar intervals use local dates and half-open bounds. Date policy is explicitly visible in UI: filters use modification time. Support reference examples without claiming arbitrary AI comprehension.

## Dependency choice

Document content indexing is opt-in via `document_settings`; `document_text` stores identity-bound text, digest, extractor version and indexed/partial/empty/failed status. External-content FTS5 triggers insert/update/delete document words; file path/size/precise-modification changes invalidate text, and root/file removal cascades it. Search ORs filename, image OCR and document FTS for each parameterized term, retaining the visibility view and all existing filters. Unchanged identities and previous failures are not repeatedly parsed. Explicit Retry clears failed/empty attempts; Clear removes document text and disables automatic indexing without touching originals/image OCR/favourites.

`document_index.rs` reserves the existing engine job slot, reads only checked visible indexed IDs in batches of 128 and checks containment/exclusions/identity before and after reads. Input is capped at 16 MiB and the read snapshot is hashed before reducing plain-text parser input to its bounded prefix; a second cancellable SHA-256 read before persistence detects changes even when metadata is preserved. Writes are gated with file actions/enable state and use a matching identity/visible-row SQL guard. Metadata watching schedules pending content work at idle (5-second polling), respecting existing cancellation/resource/pause controls. New content jobs do not scan new paths or grant root authority. Stop/cancel disables the persistent content preference and leaves completed rows searchable. Files changed while hidden remain metadata-reconciled; unhide schedules missing content later.

The app's early `--digview-content-worker` entry point runs before Tauri/single-instance/diagnostic initialization and accepts only a fixed format tag and bounded stdin bytes. It opens no document paths or library DB, executes no macros or external links, and returns bounded JSON through stdout; stderr/raw parser errors are discarded. Parent kills/waits the child on cancellation, disable, timeout (30 seconds) or process failure. Windows assigns a 512 MiB process-memory job with kill-on-close before sending input; this is process/resource isolation, not an OS filesystem sandbox. Other-platform resource/runtime behavior remains unvalidated. PDF uses pinned pdf-extract 0.12.1, capped output writer and 200-page traversal; DOCX uses pinned zip 4.6.1/quick-xml 0.41.0, whitelisted text parts (32), 2048-entry/4 MiB-part/8 MiB-total XML limits, DTD refusal and no disk ZIP extraction. UTF-8/BOM UTF-16 text/code uses a bounded prefix; output is at most 512 KiB UTF-8. Files without text, encrypted PDFs, legacy .doc, binary/unknown encodings and parse failures remain explicit skipped/no-text outcomes. Scanned PDF OCR and semantic/embedding search are separate future work. Throughput/large-library content-index size has not been benchmarked.

`native-core/visibility.rs` adds an additive `hidden_paths` table (canonical display path, normalized path key, file/folder kind) and a `visible_files` view. Literal equality and component-bounded folder-prefix comparisons avoid interpreting filenames as SQL LIKE patterns; values are bound parameters. Windows keys normalize separators and ASCII case via SQLite; Unix keys retain case/backslashes. All discovery SQL and duplicate candidates/keepers use the visibility view; raw `files` still supports reconciliation and identity retrieval, followed by a hidden check in `checked_file`. Media reads and thumbnail publication revalidate checked-file access. Hiding uses indexed IDs, existing root IDs or a native folder picker validated against unchanged registered roots, never renderer-provided paths. Batch writes/limits are transactional; operation gating prevents hiding concurrently with trash/jobs. Unhide changes only rules, preserving metadata/FTS/favourites and requiring no rescan. Folder names, descendants and replacements at the same location remain covered. Rules remain after root removal so reimporting the same path preserves intent.

With no hide rules, simple library/category/root/source counts retain cached totals. With active hide rules, counts/categories/sources use filtered SQL aggregates on blocking workers; unfiltered counters continue tracking the complete index and are immediately reusable after all rules are removed. Exact-rule lookup and folder-rule filtering have indexes. Large-library/many-folder-rule performance has not been benchmarked for this addition. Scanning/watching still reconcile hidden rows; visibility rules grant no scanning authority and do not change file contents or OS attributes.

Common totals are maintained transactionally by SQLite triggers for the full library, category, root and source. Library pages read one counter row rather than repeatedly summing the entire file table. Compound/date/text filters still run real SQL aggregates. Sorting and cleanup use dedicated indexes. WAL uses synchronous=NORMAL because this is a rebuildable metadata index; original file contents never live in SQLite. Totals changes commit atomically with the indexed file changes.

A single-instance desktop plugin prevents competing process-level scan jobs. Clipboard access is write-only and used only for explicit OCR copying.

Focused Tauri implementation. A distributed filesystem is outside the verified product scope. Prefer maintained libraries for image decode, SQLite, hashing and OS trash. Pin reproducible dependency locks. Desktop local tools open directly and work offline, with no account or authentication provider.

## Disabled observability foundation (2026-10-20)

`src/observability.ts` provides explicit PostHog Capture API events, minimal Sentry envelopes and bounded local metadata diagnostics. Production/master/channel gates fail closed; DEV/default builds do not collect or send. No vendor SDK/remote script or Rust changes. API/UI hooks pass allowlisted operation metadata only. Hosted ingestion destinations are constrained in config/CSP, storage is capped to 100 records/seven days, sink delivery is independent with retry/backoff. This is not native crash-dump integration or process startup/shutdown profiling. See OBSERVABILITY.md and STATUS.md for data boundaries and validation.

## Local discovery and updates (2026-10-20)

`native-core/discovery.rs` adds idempotent favourites/saved_searches/image_text tables and an external-content image_text_fts index. SQLite foreign keys cascade favourite/text rows on file removal; a trigger invalidates OCR when indexed size/precise modification token/path changes. Query combines parameterized filename/text FTS matches per term while retaining pagination/filter/totals behavior. Favourite queries bypass unfiltered cached totals. Search snapshots store bounded typed filter state, not executable SQL or new scan roots. OCR identity snapshots include SHA-256 checked before text persistence; native commands and fallback image workers keep file processing off the UI thread. No background all-image OCR was introduced.

`src-tauri/updates.rs` uses the pinned official updater via narrow custom commands; renderer URLs/keys are not accepted and plugin guest permissions stay denied. Shared `update_policy.rs` validates transport, decodes public keys and verifies signed bytes/version. Missing/development configuration blocks requests; notifications are opt-in. Install verifies the offer version, reserves the engine job slot and makes a SQLite VACUUM INTO snapshot before invoking the verified updater. Stable app-data identity persists settings/vault/WebView data. This is source preparation with unit/fixture evidence; native desktop adapter compilation and actual updater installation are deferred.
