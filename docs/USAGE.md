# Using DigView

**First launch:** follow Welcome → Folders → Search → Preferences, then choose **Start using DigView**. There is no separate summary/Review step. New folder choices wait for this confirmation before indexing. With selected/existing folders, the library opens directly. With no folders, an optional final screen offers Add folders or Open my library. **Set up later** keeps existing library/settings and follows the same routing. Older builds see the corrected wizard once on upgrade. Existing folders remain registered; existing indexing can continue. After completion or Set up later, normal restarts/reinstalls with retained app data skip setup. There is no reopen action; use normal Settings to edit preferences. See [installer/setup guide](INSTALLER.md).

The folder step offers Documents, Pictures, Videos, Music, Desktop and Downloads at their configured OS locations. Check only what you want indexed, or choose Choose custom folder. New suggestions start unchecked. Unavailable locations and overlaps with existing folders are disabled and explained. New indexing starts after Start using DigView on Preferences.

**Add folders after setup:** the no-folder completion screen offers **Add folders** inline; adding folders then opens the library. The library and Settings **Add folder** controls open the same suggested/custom selection view in a dialog. Check suggestions or choose **Choose custom folder**, then confirm **Add selected folders**. Cancel adds nothing. Existing folders/settings are kept; the complete wizard does not restart. Wait for an active library task to finish/cancel before confirming new roots. These source changes appear after the user's next build.

**Search inside documents:** in Settings, choose **Search inside documents → Enable content indexing**. It indexes supported PDF, DOCX, TXT and common code/config/markup files from already-selected library folders, then updates new/changed documents automatically while the app runs. Search their words in the normal top search box alongside filenames and previously recognized image text. Existing type/date/size/folder/source/favourite filters still apply. Quote words such as `"videos"` if you want literal text rather than a type clue. This is keyword/prefix search; Gemma and meaning-based search are not included.

Settings shows **indexed**, **partial**, **pending**, **no text** and **skipped** counts. **Index now / retry skipped** retries failed/no-text inputs and pending documents. Stop automatic indexing (or Cancel indexing while a content job runs) stops current work and saves the disabled preference; already-saved searchable text stays available. To remove extracted document text, choose **Clear document text index**; this also disables automatic content indexing, preserves original files/favourites/image OCR, and requires re-enabling to rebuild it. Changing/removing an indexed file invalidates its old text during normal metadata reconciliation; removing its root also removes extracted text. Hidden items remain filtered out of content search. Scanning pause/battery/resource controls apply between work units; a current parser can finish before a pause takes effect, while cancel/disable terminates its process.

Each file is limited to 16 MiB, each PDF to the first 200 pages, each text/code extraction to the first 2 MiB, and stored searchable text to 512 KiB/file. Partial files remain searchable within that prefix. PDFs need embedded text; image-only scans need separate PDF OCR, which is not implemented. Password-protected PDFs, legacy binary `.doc`, unsupported text encodings and damaged documents are skipped. Plain text supports UTF-8 and UTF-16 with a BOM. DOCX includes main-body/table text, footnotes/endnotes and common headers/footers; XML expansion is bounded. No Word installation or macro execution is used. Files/content stay on this device; extracted text is stored in the shared local library. This source addition requires a new app build before it appears in the installed app.

To hide a file, right-click it (or press Shift+F10 on a focused file control) and choose **Hide this file from app**, use **Hide from app** in its preview, or select multiple files and use **Hide from app** on the selection bar. The file actions dialog also offers **Hide containing folder and contents**, showing the folder before the action. In Settings → Selected folders, the eye-off action hides a complete selected root. In **Settings → Hidden items → Hide folder…**, choose any folder within an already-selected library root; this does not add a new scan root.

Hidden items disappear from library/search/favourites/duplicates/cleanup and their counts. Folder rules include all descendants and future indexed children. **Settings → Hidden items** lets you find and **Unhide** rules; results return immediately from the current index, without rescanning. If an item stays hidden, remove any remaining rule for its containing folder or the file itself. Rules persist across restarts, rescans and removing/re-adding the same root. They are tied to paths: after renaming/moving a hidden file or folder, hide its new location too. Up to 1000 rules and 500 files per batch are supported. Hide actions require the selected location to be available and library jobs finished/cancelled; Unhide also works for unavailable paths. Originals, Windows attributes, favourite marks and recognized text are kept. Scans still index these paths; this is app visibility, not a scan exclusion or password lock, and it applies to the shared local library. Source only until the next app build.

Current source also shows cached video frame thumbnails in grid/list views on Windows. Extraction runs locally on a blocking worker for indexed files in your selected folders. Installed Windows codecs determine supported formats; unavailable frames retain the video file icon. No FFmpeg installation is required by the app. Existing EXE/installers need a new build to include this change.

Current source adds in-app PDF, video/audio and text previews plus local diagnostic logging. These additions require a new app build; existing release artifacts are unchanged. PDF page navigation, fit/zoom and local password entry are available up to 40 MB. Media controls provide play/pause, volume and seeking; codec support depends on the system, with Open original as fallback. Text/code is read only (including HTML), supports UTF-8 and UTF-16 with BOM and shows at most the first 256 KB with a truncation notice. PDF scripts/attachments/forms are not interactive, and there is no PDF text-selection layer. Closing the preview stops playback/worker work and revokes its native session.

For issue reports, use **Settings & folders → Local diagnostics → Export logs** or **Export local logs** on the login screen, then share the saved file. Local logs rotate at roughly 4 MiB total; cloud reporting stays off. Details: [DIAGNOSTICS.md](DIAGNOSTICS.md).

After first-run setup, the app opens directly into your local library. No account, email code, password or online activation is needed for local file features. Choose folders explicitly before indexing; existing library data and settings remain on this device.

Choose **Settings & folders → Appearance → Light, Dark or System**. The sun/moon button in the header switches directly between Light and Dark; choose System again to follow your device. Your preference is saved on this device and restored when the app opens.

1. Open the desktop app and choose **Add folder**. Files stay in their original locations. You can add several non-overlapping folders.
2. Browse categories or **All files**. Use grid/list, sorting and the folder filter. Large libraries load in pages; scanning shows partial results as they become available.
3. Search with filename words or clues such as `PDFs from last week`, `screenshots from last month`, or `videos larger than 500 MB`. The chips show interpreted filters. Dates use modification time. Quote phrases to keep clues literal. Ctrl/Cmd+F focuses search; Escape clears it.
4. Preview an image and choose **Recognize text**. Highlight part of the recognized text and use **Copy selected** or Ctrl/Cmd+C; **Copy all** copies the complete result. Processing stays on device. Windows uses its installed OCR languages; the bundled fallback supports English. Current source also previews PDFs, video/audio and text/code inside the app; see the limits above. Unsupported files still offer **Open original**.
5. **Downloaded from** shows origins saved in file metadata. Missing origin metadata stays unknown; no cloud-account sign-in is involved.
6. Run **Duplicates** to calculate exact hashes. Select extra copies, review the confirmation and move them to the system trash. The engine rechecks contents and preserves a verified keeper. **Clean up** also offers large files, old screenshots and forgotten downloads.
7. Restore trashed files using Windows Recycle Bin or your operating system's Trash, then refresh. Use **Settings & folders** to remove a folder from the index without deleting its originals.

Cancelling a library task also pauses automatic indexing for 30 seconds, so a queued recovery scan does not immediately restart the cancelled work.

In **Settings & folders → Background & startup**, choose whether the close button keeps the app running in the system tray. This is on by default. Click the tray icon or choose **Open DigView** to reopen; **Quit DigView** fully exits and stops background indexing. Turning off **Keep running when closed** restores normal close-to-exit behavior. Launching the executable again opens the existing window.

**Run at startup** is off until enabled and currently supports Windows sign-in only. Keep the executable in a permanent location before enabling it. Disable startup before moving/removing that executable, then enable it from its new location. **Start minimized at login** starts in the tray when background mode is enabled; a normal manual launch always opens the window. Windows Startup Apps/Task Manager can independently block startup; the app reports its own Run registration, not an actual sign-in result. A sign-in/sign-out test remains pending.

While the desktop app is running, selected folders update automatically. File events are batched; a file's size and modification time must settle for about two seconds before an incremental update. Browser `.crdownload`, `.part`, `.partial` and `.tmp` files are excluded until renamed. This is a settling heuristic, not a guarantee that every third-party downloader has finished writing. Startup, newly watched folders, directory changes and reported event loss trigger recovery scans; Refresh remains available for changes the filesystem does not report. Watching stops after a folder is removed or the app exits. A browser preview uses synthetic sample data and cannot operate on files. The current development release has no paid activation. Native validation status and platform limitations are recorded in VALIDATION.md.

In the next source build, **Settings & folders → Scanning & resources** provides **Pause scanning / Resume scanning**. Manual pause persists across restart and applies to full scans, duplicate hashing and automatic updates. Cancel remains available in the progress bar, including while paused. Resume continues the in-flight task; when idle, pending changes receive a recovery scan. Removing/changing folders still requires the current task to finish or be cancelled.

**Low-resource mode** inserts 8 ms cooperative breaks per scanned entry/incremental event and per 256 KiB duplicate hash chunk. It is a soft throttle, with no guaranteed CPU percentage or disk bandwidth. **Pause heavy work on battery** is opt-in on Windows; work resumes on AC power. Unknown/unavailable battery status does not suspend work. Preview/OCR and explicit cleanup validation are separate from these scan controls.

Enter **exclusions** one per line: `Private` excludes that component beneath every selected root, `Work/Secret` excludes a root-relative file/subtree, and `*.log` excludes an extension. Paths must be relative, without `..`, absolute prefixes or general globs. Windows matching is case insensitive. At most 100 rules, each 512 bytes; built-in system/development/temp exclusions remain enabled. Save while idle (cancel any paused task first). A successful recovery scan removes excluded index rows, never originals. Re-enabling a path schedules reindexing. Excluded indexed files cannot be opened/hashed/trashed through checked-file actions while reconciliation is pending.

**Folder availability** shows the full selected path, availability and last completed scan timestamp. Unavailable folders retain their indexed files. While the app runs, watcher attachment retries roughly once per second; reconnection schedules a settling/recovery scan. Redirected roots are refused. Manual Refresh is still the recovery option for filesystem notification failures. Physical USB/network reconnect and actual battery transition smoke remain pending until the user requests a new app build.

Default exclusions are visible under **Scanning & resources → Default exclusions (always enabled)**. They include node_modules, .git/.hg/.svn, Rust target, Python .venv/venv/**pycache** and test/type/lint caches, .tox, framework .next/.nuxt/.svelte-kit/.angular/.parcel-cache/.turbo caches, .gradle/.vs, OS trash/system metadata, .DS_Store/Thumbs.db/desktop.ini, temporary download extensions and Python bytecode. The backend supplies this shared list to the UI; custom rules add to it. These defaults apply to existing saved preferences too, without replacing custom rules. Broad names build/dist/bin/vendor are left available because they may contain useful deliverables. Original files are never removed; default-excluded existing index rows are reconciled on the next successful scan. Source only until the requested final app build.

Open a file preview and choose Add to favourites, then use Favourites in the sidebar. Favourite marks stay with the indexed ID; a rename/reimport creating a new ID needs a new mark. In current source, click/focus the top search input (or Ctrl+F) to open recent and saved searches; saved searches no longer occupy the sidebar. Enter a name in this dropdown and choose Save current filters. Relative date clues such as last week are interpreted again when restored. A removed saved folder produces an error instead of broadening the search. Saved searches and favourites are local to this device.

Recent search text is recorded on Enter or leaving the search area, with up to 10 distinct queries stored locally across restarts. Click a recent query to search again using current filters. Clear recent removes only this history, preserving saved filters, favourites and the active query. Outside click/Tab away/Escape closes the dropdown; Escape while it is open preserves search text. Storage failures show a message. These dropdown/history changes need a new app build to reach the installed application; no installer was rebuilt for this source change.

Recognize text from an image preview to include it in ordinary library search; it reappears when reopening that image. Select up to 50 images in a library page and choose Index image text for sequential local processing. Stop after current image cancels remaining images; the active local recognition finishes (existing native OCR timeout is 90 seconds). Failed images are counted and skipped. Use quotes to search literal text when words would otherwise be interpreted as type/date clues. Scans do not automatically OCR every image. When a rescan detects changed size/modification/path, old OCR text is discarded and you can recognize again. Settings → Searchable image text → Clear recognized text index removes only extracted search text.

Settings → Scanning & resources → Retry selected folders starts a manual scan of existing selected roots; unavailable roots retain index rows. Settings → App updates offers manual and opt-in automatic update checks when production configuration exists. Review update shows a separate confirmation; download, signature/version verification and a local DB backup precede installation. Existing builds have no configured update service. Production setup and actual upgrade testing are tracked in UPDATES.md.
